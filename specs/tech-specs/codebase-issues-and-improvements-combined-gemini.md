# Codebase Issues and Improvements

This document combines findings from multiple audits of the Streamlit codebase, identifying the top 20 security vulnerabilities, correctness bugs, and performance opportunities. These issues can generally be addressed with internal changes that do not require user-facing API modifications.

## 1. Blocking Event Loop in Origin Check (DoS Risk)
**Location:** `lib/streamlit/net_util.py`, `lib/streamlit/web/server/server_util.py`
**Description:**
The `is_url_from_allowed_origins` function performs a **synchronous, blocking HTTP request** to `http://checkip.amazonaws.com` (with a 5-second timeout) if the external IP is not cached. This occurs during the WebSocket handshake (`check_origin`).
**Impact:**
An attacker can initiate multiple WebSocket connections with non-local origins, causing the server's main thread to block for up to 5 seconds per request, effectively denying service to all other users (DoS).
**Remediation:**
Make `get_external_ip` asynchronous or run it in a thread executor.

## 2. Unbounded Memory Usage in File Uploads (DoS Risk)
**Location:** `lib/streamlit/runtime/memory_uploaded_file_manager.py`, `lib/streamlit/web/server/upload_file_request_handler.py`
**Description:**
1. `MemoryUploadedFileManager` stores all uploaded files in a Python dictionary without a **global or per-session total size limit**.
2. `UploadFileRequestHandler` uses `tornado.httputil.parse_body_arguments`, which buffers the entire multipart payload into memory before validating the session.
**Impact:**
An attacker can exhaust server memory (OOM) by uploading many files or sending massive payloads to invalid sessions.
**Remediation:**
- Implement global and per-session memory caps.
- Use Tornado's streaming request body support to validate headers/session before buffering data.

## 3. Missing Session Validation on File Delete (Security)
**Location:** `lib/streamlit/web/server/upload_file_request_handler.py`
**Description:**
The `DELETE /_stcore/upload_file/<session>/<file>` endpoint blindly removes the specified file. Unlike the `PUT` endpoint, it **does not check if the `session_id` is active**.
**Impact:**
An attacker who guesses a session ID can delete uploaded files belonging to that user, disrupting their session.
**Remediation:**
Add `if not self._is_active_session(session_id): ...` validation to the `delete` method.

## 4. Unsafe Custom Component v2 Execution (XSS Risk)
**Location:** `frontend/lib/src/components/widgets/BidiComponent/hooks/useHandleHtmlAndCssContent.ts`
**Description:**
The Custom Component v2 implementation injects HTML and JS provided by the component author directly into the DOM (via `createContextualFragment` or `innerHTML`) without sanitization.
**Impact:**
This creates a Cross-Site Scripting (XSS) vector if a user loads a malicious component. Unlike v1 components (iframed), v2 components have full access to the app's DOM and context.
**Remediation:**
Document this risk clearly, and consider adding an optional "safe mode" that sanitizes content or enforces sandboxing.

## 5. Cross-Origin WebSocket & Download Hijacking (Security)
**Location:** `lib/streamlit/web/server/browser_websocket_handler.py`, `lib/streamlit/web/server/media_file_handler.py`
**Description:**
1. When `server.enableCORS=false`, `check_origin` returns `True` for **all** origins, allowing any site to connect to the WebSocket.
2. `MediaFileHandler` sets `Access-Control-Allow-Origin: *` when CORS is disabled or broadly configured, allowing any site to read user downloads.
**Impact:**
An attacker's site can open a WebSocket to the backend (hijacking the session) or fetch sensitive user data generated by `st.download_button`.
**Remediation:**
- Decouple WebSocket origin checks from the `enableCORS` flag; always enforce an allowlist for WebSockets.
- Scope `Access-Control-Allow-Origin` to the requesting origin with credentials only when permitted.

## 6. HostCommunication postMessage "*" (Data Leak)
**Location:** `frontend/lib/src/hostComm/HostCommunicationManager.tsx`
**Description:**
`sendMessageToHost` uses `window.parent.postMessage(..., "*")`.
**Impact:**
If the Streamlit app is embedded in an iframe, **any** parent origin can receive the app's messages (containing widget states, metadata, etc.), even if it wasn't the intended host.
**Remediation:**
Restrict `postMessage` target origin to the validated host origin determined during the handshake.

## 7. Broad Default postMessage Allowlist (Security)
**Location:** `lib/streamlit/web/server/routes.py`
**Description:**
Self-hosted apps default to trusting messages from `*.streamlit.app`, `*.streamlitapp.com`, etc.
**Impact:**
An attacker controlling a subdomain on Streamlit Cloud (or a compromised one) could send privileged commands to a self-hosted app if the user visits the attacker's site (and the app is embedded).
**Remediation:**
Default to an empty allowlist or `self` for self-hosted instances; require explicit configuration to trust external hosts.

## 8. Fallback to `__reduce__` in Hashing (RCE Risk)
**Location:** `lib/streamlit/runtime/caching/hashing.py`
**Description:**
When an object is not natively supported by the hasher, the code falls back to `obj.__reduce__()`.
**Impact:**
`__reduce__` is the mechanism used by `pickle`. If untrusted data reaches this code path (e.g., via a malicious object injection elsewhere), it could trigger arbitrary code execution during the hashing process.
**Remediation:**
Disable `__reduce__` fallback or strictly limit it to safe types. Log a warning when it's used.

## 9. Pickle Deserialization in Cache (RCE Risk)
**Location:** `lib/streamlit/runtime/caching/cache_data_api.py`
**Description:**
Cached data is serialized/deserialized using `pickle`.
**Impact:**
If an attacker gains write access to the filesystem (e.g., via a separate vulnerability), they can poison cache files. Reading these files triggers RCE.
**Remediation:**
Sign cache files with a secret key (HMAC) to ensure integrity before unpickling.

## 10. AppStaticFileHandler Allows All CORS Origins (Data Leak)
**Location:** `lib/streamlit/web/server/app_static_file_handler.py`
**Description:**
Static files served by the app unconditionally have `Access-Control-Allow-Origin: *`.
**Impact:**
Any external website can embed/read resources from `static/`. If users put sensitive data there, it is public to the web.
**Remediation:**
Restrict CORS for static files to the same origin or configured allowed origins.

## 11. Blocking File I/O in Async Server (Performance)
**Location:** Multiple (`ComponentRequestHandler`, `LocalDiskCacheStorage`, `ScriptCache`)
**Description:**
The codebase frequently uses synchronous `open()` and `read()` calls within the asynchronous Tornado event loop.
**Impact:**
Loading large component assets, reading cache files, or reloading scripts blocks the server, causing latency spikes for all users.
**Remediation:**
Use `aiofiles` or `loop.run_in_executor` for all file I/O.

## 12. Secrets Exposed in `__repr__` (Info Leak)
**Location:** `lib/streamlit/runtime/secrets.py`
**Description:**
The `Secrets` class `__repr__` method outputs the full content of the secrets.
**Impact:**
Accidental logging of the `st.secrets` object (e.g., in a traceback or debug log) writes credentials to plain text logs.
**Remediation:**
Modify `__repr__` to redact values (e.g., `<Redacted>`) or show keys only.

## 13. Cookie Security Configuration (Security)
**Location:** `lib/streamlit/config.py`, `frontend/lib/src/util/utils.ts`
**Description:**
1. `server.cookieSecret` is randomly generated on startup by default, invalidating sessions across restarts/replicas.
2. Client-side cookies (`ajs_anonymous_id`) lack `Secure` and `SameSite` attributes.
**Impact:**
- Session instability in production.
- Cookies can be intercepted or used in CSRF attacks.
**Remediation:**
- Warn if `cookieSecret` is random in production.
- Add `Secure; SameSite=Lax` to client-side cookies.

## 14. Race Conditions in File Managers (Correctness)
**Location:** `lib/streamlit/runtime/memory_uploaded_file_manager.py`, `lib/streamlit/runtime/media_file_manager.py`
**Description:**
`MemoryUploadedFileManager` uses a `defaultdict` without locks. `MediaFileManager` has potential races during orphaned file cleanup.
**Impact:**
Concurrent requests can corrupt internal state, causing file uploads to fail or be lost.
**Remediation:**
Add `threading.Lock` around all shared dictionary access.

## 15. Unbounded Metrics Queue (Performance/DoS)
**Location:** `frontend/app/src/MetricsManager.ts`
**Description:**
Events are pushed to `pendingEvents` without a limit while waiting for initialization.
**Impact:**
If initialization hangs or fails, the queue grows indefinitely, causing memory bloat on the client.
**Remediation:**
Cap the queue size (e.g., 100 events) and drop old events.

## 16. Memory Leak in Cache Locks (Performance)
**Location:** `lib/streamlit/runtime/caching/cache_utils.py`
**Description:**
`_value_locks` (locks per cache key) are created on demand but never cleaned up, even when cache entries expire.
**Impact:**
Long-running apps with many unique function arguments will leak memory (lock objects).
**Remediation:**
Clean up unused locks periodically or when cache entries are removed.

## 17. Missing Security Headers (Security)
**Location:** `lib/streamlit/web/server/routes.py`
**Description:**
Responses lack standard security headers: `Content-Security-Policy` (CSP), `Strict-Transport-Security` (HSTS), and `X-Frame-Options`.
**Impact:**
Increases susceptibility to XSS, protocol downgrade attacks, and Clickjacking.
**Remediation:**
Add a default middleware to inject these headers (configurable).

## 18. Hash Collisions in Sampling (Correctness)
**Location:** `lib/streamlit/runtime/caching/hashing.py`
**Description:**
Large DataFrames are hashed by sampling a fixed number of rows/bytes.
**Impact:**
Different DataFrames could produce the same hash if the sampled regions are identical, leading to incorrect cache hits.
**Remediation:**
Include metadata (shape, column names, dtypes) and head/tail rows in the hash to minimize collision probability.

## 19. Path Traversal in Secrets (Security)
**Location:** `lib/streamlit/runtime/secrets.py`
**Description:**
`_parse_directory` follows entries in a directory without explicitly checking if they are symlinks pointing outside the root.
**Impact:**
If an attacker can create symlinks in the secrets mount (unlikely in standard K8s, but possible in other setups), they can read arbitrary files.
**Remediation:**
Use `os.path.realpath` and ensure the target is within the secrets directory.

## 20. Silent Config/Serialization Failures (UX)
**Location:** `lib/streamlit/config.py`, `lib/streamlit/runtime/state/session_state.py`
**Description:**
- TOML parsing errors are logged but execution continues.
- Session state serialization checks happen only at script end.
**Impact:**
Users are unaware of misconfigurations or bugs until later, leading to confusion.
**Remediation:**
Raise exceptions for config errors in non-dev modes. Check session state serialization on assignment (optional mode).
